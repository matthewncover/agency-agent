## R1 — Psychology
*Source (full rationale + citations): `doc/research/psychology.md` v0.2.*
 
- **D-1 — The 95% Floor is self-efficacy calibration; the *need* is the performance-relevant bar, the *want* is optional reach / next-floor-in-waiting.** Rationale: in a longitudinal self-directed-adherence domain, performance-over-time *is* compounding self-efficacy (Bandura, mastery experiences); Locke-Latham "hard goals win" is scoped to single-episode task performance and doesn't bind here. *Reverses v0.1's "needs = consistency, wants = performance."* → **MVP · vision.md + behavior-spec.md (need/want semantics) · ADR?** (foundational; reverses a prior position). *(psych §2.1)*
- **D-2 — Add three design objectives: build self-efficacy/self-trust, maximize agency, protect intrinsic motivation.** Rationale: each is the evidence-grounded "why" under existing mechanics; self-trust operationalizes the spec's existing "keep promises to yourself." → **MVP · vision.md (objectives) · ADR?** (objectives are load-bearing). *(psych §1b)*
- **D-3 — Optional implementation-intention (when/where/how) prompt at lock-in, hardest-or-carried-over item only, never daily-forced.** Rationale: if-then benefit (d≈0.65) concentrates on slip-prone goals; daily friction would kill usage, and usage dominates long-run EV. → **MVP · behavior-spec.md · no ADR.** *(psych §2.3)*
- **D-4 — Suppress "days left in chapter" countdowns; surface wins across all time, not per-chapter.** Rationale: anticipated landmarks suppress run-up effort (Koo 2020) and metric resets cut both ways (Dai 2018) — keep the fresh-*start*, drop the ending drag and the slate-wipe. → **MVP · behavior-spec.md · no ADR.** *(psych §2.5)*
- **D-5 — Recurring-goal reassessment offers retire/redirect, not only lower-the-bar; human-chosen; `paused` is the on-ramp.** Rationale: disengaging from genuinely-wrong goals protects well-being (Wrosch); "never auto-drop" preserved since the human decides. → **MVP · behavior-spec.md (lifecycle enum already has `paused`) · no ADR.** *(psych §2.4)*
- **D-6 — Explicit non-goal: no consecutive-day streak counts, no loss-framed nudges.** Rationale: streak/loss-aversion mechanics reproduce the report-card / self-criticism dynamic the system is built against; carry-over-with-~1-week-berth is already the healthy grace-day pattern. → **MVP · CLAUDE.md (non-negotiables) + behavior-spec.md · ADR?** (guardrail a future gamification change could violate). *(psych §3.1)*
- **D-7 — Surfaced wins tie to why/meaning/values, not counts; required daily element; weighted ≥ miss-reflection salience.** Rationale: progress principle + competence (SDT); negativity asymmetry makes win-surfacing load-bearing, not decorative; meaning-link also protects intrinsic motivation (D-2). → **MVP · behavior-spec.md · no ADR.** *(psych §2.6)*
- **D-8 — Autonomy-supportive (offer-not-directive) phrasing is a hard rule; agency-maximizing is an objective; the lighter-day nudge is *information*, not a recommendation, for the high-autonomy user; challenges framed as decline-able dares.** Rationale: controlling framing flips autonomous→controlled motivation and triggers *active* reactance in the Enneagram-8. → **MVP · vision.md (objective) + CLAUDE.md (non-negotiable) + tone layer · ADR?** *(psych §2.8, §1b)*
- **D-9 — At chapter-setting, surface last chapter's actual hit-rate next to each proposed bar.** Rationale: outside-view corrective for the optimistic "95% sure" judgment. **Reclassified MVP → post-MVP (deferred-by-dependency):** requires "same goal, last chapter" lineage, which D-18 / ADR-0013 deliberately severs (rollover mints fresh goals with fresh IDs); not buildable in MVP without re-adding the dropped lineage, and the within-chapter-only version doesn't answer the bar-setter's question. ADR-0013 already records D-9 as post-MVP — this line catches the inbox up. → **post-MVP · behavior-spec.md §4 (recorded deferred) · no ADR.** *(psych §3.4; ADR-0013; spec §10; behavior-spec §4)*
- **D-10 — Keep cross-person comparison out of surfaced views (principle now); explicit comparison-suppression feature is post-MVP.** Rationale: two high-Competition achievers on a shared surface risk support→comparison drift; the partner is a witness, not a scoreboard. → **principle MVP / feature post-MVP · behavior-spec.md · no ADR.** *(psych §2.7, §3.6)*
### Deferred — committed, post-MVP
- **OQ-PSY-1 — Upward (offensive) recalibration.** Detect a floor **cleared with room to spare** over N weeks and *offer* to raise it (or promote the want to the new need). **Status: deferred (not in MVP).** Why deferred: not needed for a working MVP loop. Natural home if revived: the autonomy-supportive *dare* framing (D-8). **Candidate trigger rejected:** *"need cleared ≥95% of days for ≥2 weeks"* is **cadence-blind** — it silently assumes daily goals ("13/14 days" is meaningless for a 3×/week, interval, or fixed-schedule goal). Any future trigger must be expressed in the **goal's own scheduled occurrences** ("cleared on N of last M occurrences"), never in calendar days. Trigger left undesigned, deferred. *(psych §4; behavioral convergence pass)*

## R2 — Existing-tools research
*Scope note: this surveys existing goal/habit tools to borrow mechanics and dodge anti-patterns for **our own** two-person (later family) bot — not market/competitive analysis for a public product.*
*Source (full per-tool notes + mapping): `doc/research/competitive.md` v0.1.*
 
- **D-11 — EOD reflection carries an honest obstacle-vs-avoidance distinction (the "legitimacy check," stripped of any penalty); stays an optional, fast prompt.** Rationale: honest self-mapping is what makes a miss *actionable* — self-deception warps the map, and you can't act with clarity on a warped map. This is the principle that makes "misses-as-data" actually work, not just a slogan. → **MVP · behavior-spec.md · ADR?** (foundational to misses-as-data). *(comp §2 Beeminder, §3A1)*
- **D-12 — The heavy-day trim is load-bearing, not UX polish; on heavy days the AI proactively proposes a trimmed subset, full-list override always one tap away.** Rationale: gentle tone is insufficient — goal pile-up itself breeds guilt (Finch failure mode); Sunsama's capacity warning validates treating achievability as a first-class feature. → **MVP · behavior-spec.md · no ADR.** *(comp §2 Finch/Sunsama, §3A2)*
- **D-13 — Friction is a ratchet: each iteration must lower friction, never raise it; explicit anti-pattern is ritual-creep (Sunsama/Whoop-style heavy daily rituals, structured intake forms).** Rationale: usage dominates long-run value; well-intentioned structure that adds friction kills the thing it's meant to support. Sharpens objective 2. → **MVP · vision.md (objective 2) + CLAUDE.md (non-negotiable) · ADR?** (guardrail a future "nice feature" could violate). *(comp §2 Sunsama, §3A)*
- **D-14 — No gamification, full stop: explicit non-goal covering points, XP, HP, levels, badges, pet economies, avatars, scores. Extends D-6 (streaks/loss-framing) to the whole family.** Rationale: gamification reduces to extrinsic motivators + dependency on the reward system rather than the habit; intrinsic motivation is the target (D-2). *Note: meaning-tied win-surfacing (D-7) is excluded from this ban — it has no score.* → **MVP · CLAUDE.md (non-negotiable) + vision.md · ADR?** (guardrail). *(comp §2 Habitica, §3B)*
- **D-15 — No in-app social, props, or comparison mechanics for the couple/family scope; encouragement stays human-to-human in the shared chat.** Rationale: it's already a shared chat — free-form props are richer and carry no obligation or comparison risk. Complements D-10 (comparison suppression) on the build side. → **MVP · behavior-spec.md + CLAUDE.md · no ADR** (folds in; overlaps D-10). *(comp §2 Coach.me, §3B)*
- **D-16 — Lowering a need's bar is instant and at the owner's discretion (no akrasia-horizon cool-down); the change is visible to the partner for optional discussion. Rejects the Beeminder harder-now/easier-later asymmetry.** Rationale: autonomy-first (D-8) outweighs the "keep need honest" gain, and it simplifies the app. The real tradeoff — frictionless lowering could let someone quietly erode a need during a bad week — is mitigated by *visibility + a human conversation*, the appropriate honesty mechanism in a two-person trusted context (the horizon matters more for solo self-deception). → **MVP · behavior-spec.md · no ADR** (confirms spec §3; records a considered-and-rejected alternative). *(comp §4 OQ-1)*
**Confirmation only (no new decision):** completion-advanced rotation (spec §5) is independently corroborated by Reclaim's reopen / manual-start behavior. Already Decided; logged for traceability, not for action.
 
### Resolved (behavioral convergence pass)
- **OQ-COMP-1 — RESOLVED: "name the bar, not the streak."** The report-card harm decomposes into **verdict + score + comparison**; strip those three and the bot can be fully honest about the *bar–behavior mismatch* without the harm. (1) Attribute the pattern to the **bar's calibration**, never the person ("the bar may be above your floor," never "you keep failing this"). (2) **Losses never surface unprompted** — the nudge leads with the offer; miss data, *including any count*, appears **only after the user explicitly agrees to look**; a count never headlines. (3) Keyed only to **engaged** misses (INV-1/INV-2 — never silence). (4) Tier-3 contextual patterns are offered as **hypotheses the user confirms/rejects** (D-11), never verdicts. (5) Never comparative (D-10/D-15). The bright line (no unprompted losses, no headlined count) is **profile-independent** — deliberately not branched on the Enneagram/Strengths layer, the weakest evidence in the project, precisely because miss-naming is the riskiest path. → **MVP · behavior-spec.md §7c · no ADR** (folds in; affects phrasing the LLM wraps around the §3.2 reassessment tools, not tool shapes). *(was competitive OQ-3; behavioral convergence pass)*

## Behavioral convergence pass (synthesis)
*Source: `behavior-spec.md` v0.1 (consolidation of D-1–D-16 + the two invariants + §3 reassessment/carry-over + §7a framing model). Closes the R1/R2 behavioral layer into a canonical doc; resolves OQ-COMP-1; reclassifies D-9; rejects the OQ-PSY-1 candidate trigger (all recorded in place above).*
 
- **INV-1 — NULL-TOLERANCE: non-entry is never evidence against the person.** Silence produces no tool call; an unanswered touchpoint stays `planned`/neutral and nothing punitive keys off it. Structurally enforced (mcp-tools §1 corollary, §4.1), not a rule the LLM must remember. → **MVP · CLAUDE.md (non-negotiable) + behavior-spec.md §1 · ADR?** (named design invariant; guardrail a future "engagement" feature could violate). *(spec §10; behavior-spec §1)*
- **INV-2 — ENGAGEMENT-NOT-FAILURE: the reassessment counter advances only on engaged-but-unmoved days, never on silence; no "log your miss" step, ever.** The engaged-vs-silent distinction is inferred from whether the touchpoint was answered, never asserted by the LLM. → **MVP · CLAUDE.md (non-negotiable) + behavior-spec.md §1 · ADR?** (guardrail; sibling to INV-1). *(spec §10; behavior-spec §1; mcp-tools §4.1)*
- **CTX-1 — Morning context window (MVP).** Morning turn context = Tier-1 authored profile + compressed Tier-3 digest + today's injected plan + a rolling **~1 week** of conversation. The rolling window dissolves the "what survives a reset" sub-question (no reset event to design around). Build-time note: "1 week of conversation" = raw transcript, which partly overlaps Tier-2 structured events; if token cost bites with two chatty users, fall back to "1 week of Tier-2 events" — a swap, not a redesign. Home: agent-runtime module spec (no runtime doc exists yet; recorded here meanwhile). → **MVP · agent-runtime / architecture (when written) · no ADR.** *(mcp-tools §5; behavioral convergence pass)*
