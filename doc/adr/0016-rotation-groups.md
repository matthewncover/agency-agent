# ADR-0016: Rotation groups — cadence is scheduled across member goals, not inside one

**Status:** Accepted

## Context
Local testing (2026-07-03) surfaced a scheduling failure: push-ups and pull-ups are two `interval` goals, but the real pattern is one alternating rhythm (push → rest → pull → rest …). Each interval goal's clock runs only off its **own** `last_completed_at` (`recurrence.py`), so nothing couples the two — they drift into phase and both surface the same day. Interval cannot express "these goals share one rhythm," and a miss on one must push the *other* goal's next session too.

The spec anticipated the shape of the fix: §5's rotation redesign notes the workout case is really **progression** (what's next — a pointer) × **cadence** (is today a session day — spacing/rest), flagged as a post-MVP refinement. The label-based `rotation` recurrence type covers progression *within one goal*, but merging push-ups and pull-ups into one label-rotation goal was rejected: need/want bars live per **(goal, level)** version (`0002_goalbot_schema.sql`), and carry-over counters, reassessment, re-anchoring, quantity logging, and win lineage all hang off per-goal machinery. One merged goal ⇒ one shared need bar and one shared want bar across two different movements, and "did 35 pull-ups against a need of 20 / want of 30" becomes unloggable. Session identity must stay goal identity.

Verification also found two implementation bugs in the existing label rotation, against spec §5: (1) rest slots consume **zero calendar days** — `rotation_current_index` skips rest labels instantly at surfacing time, so completing push on Friday offers pull on Saturday; (2) the pointer advances from the **stored** index, not the **surfaced** one (`advance_rotation`), so a session reached by skipping rest surfaces twice in a row. These are spec-compliance fixes, not decisions, but the corrected walk is shared with this design.

## Decision
- **New table `goalbot.rotation_group`** (append-only migration): `id`, `owner_profile_id` (person or group, same rule as goals), `name`, `sequence` (jsonb, ordered), `rotation_index` (int, default 0), `last_completed_at` (timestamptz, nullable), `created_at`, `archived_at`. Pointer state lives **on the group row** — a group is a scheduler, not a goal: it has no versions, no need/want, no wins, and is never itself completable.
- **`sequence` entries are either a member-goal reference or a rest slot**: `{"goal_id": N}` | `{"rest": true}`. jsonb mirrors the `recurrence_config` convention; goal refs are **validated at write** in the application layer (same precedent as the person-only FK rule, spec §6), not by DB constraint.
- **Member goals stay first-class goals**, each keeping its own need/want versions, `target_quantity`, quantity logging, carry-over counter, and win lineage. The day's plan item points at the **member goal itself**, so outcome logging is completely unchanged.
- **A goal referenced by an active rotation group is excluded from independent recurrence classification; the group is its sole scheduler.** Members keep their natural authored `recurrence_type` (e.g. `interval`) as inert config — if the group is archived, they degrade gracefully back to self-scheduling.
- **Due logic (date-aware rest walk).** Let `d` = days since `last_completed_at.date()` (∞ if never completed). Walk from `rotation_index`, skipping entries whose goal is not active (they consume zero days); the next member entry is **due iff `d ≥ (rest slots between pointer and it) + 1`**. Not yet due ⇒ nothing surfaces (it's a rest day). Exactly one member can be current — same-day collisions are structurally impossible. Surfaces **must-show**, like rotation today.
- **Advance on `done` only, from the surfaced index.** When the surfaced member's item is logged `done`: `rotation_index ← (surfaced entry index + 1) mod len`, stamp `last_completed_at`. On `not_done`: pointer **holds** (the member's own carry-over counter advances via the existing machinery); everything downstream shifts automatically. On silence: **no state change anywhere** (NULL-TOLERANCE — the item stays `planned`, the pointer holds, and the rest walk keys off `last_completed_at`, so an unanswered day never reads as a miss).
- **The label-based `rotation` recurrence type stays** for single-goal sequences (upper/lower/rest inside one goal identity), with the two mechanical fixes above applied to its (now shared) walk. Groups are for sequences whose sessions need **separate goal identity** — own bars, own logging, own lineage.
- **Ingestion:** the goal-markdown template gains a rotation-group block naming member `gid`s in order with rest slots; groups are authored structure, created deterministically at ingest. Pointer correction mirrors `set_rotation_pointer` (mcp-tools §3). No new daily input of any kind (friction ratchet).

## Consequences
- The push/rest/pull/rest case works end-to-end: push done Friday ⇒ pull due Sunday; push missed Friday ⇒ push re-surfaces Saturday and pull shifts to Monday — with both movements keeping independent need/want bars and quantity logs.
- Spec §5's deferred **progression × cadence** split lands: progression = the group pointer; cadence = rest slots consuming calendar days. `interval` stays a truly independent clock — no cross-goal coupling hacks bolted onto it.
- **Chapters (ADR-0013):** member goals are chapter-scoped, and rollover mints fresh goal ids — so ingest **re-resolves group membership by `gid` within the new chapter** at rollover. Groups referencing closed goals are stale by construction; ingest is the reconciliation point.
- Classification gains one pre-step (group-membership check before per-goal recurrence routing); app layer gains write-time validation of `sequence` goal refs.
- No streaks, no penalties introduced: a held pointer is the *whole* consequence of a miss, and silence changes nothing (non-negotiables 1, 2, 6 respected structurally, not just in phrasing).
